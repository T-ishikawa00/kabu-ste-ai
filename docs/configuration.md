# 設定の型・構造とサンプル

元の `config_loader.py` の16クラス・93個の型付きフィールドをASTで読み、値をコピーせず `config/schema.json` と `config/declared-types.json` を作成しました。型注釈からの静的な構造説明で、旧runtimeがこのJSON Schemaで検証していたという意味ではありません。

`config/config.example.json` は新規の人工設定例です。銘柄配列は空、資格情報はnull/空、通知フラグはfalse、接続先は予約済みの例示ドメイン、modeはARCHIVE_REFERENCE_ONLYです。旧運用設定を転記していません。安全なツールはこの例を実設定としてロードしません。

`.env.example` は環境変数名と空欄だけを示します。実資格情報を入力したファイルは追跡しません。ここから `config.yaml` を作成して旧システムを試運転する手順は提供していません。

## 実設定との違い

| 項目 | 元コードの構造 | 今回の扱い |
| --- | --- | --- |
| symbols / portfolio / trading | 銘柄、建玉数、取引方式 | 型を保持。実銘柄・数量は転記しない |
| risk / safety / short / exit | 損失・時刻・停止・間隔・決済条件 | 宣言の型を保持。実設定値は転記しない |
| api / notification | 認証・接続先・外部通知 | フィールド名と型のみ。値は非収載 |
| logging / telemetry | CSV・JSON保存先、間隔 | 出力の構造を説明。生ログは非収載 |
| paper_trading / mode | 原本の既定にlive向け経路が存在 | 元実装を保持し、危険性を明記。paperは通信遮断を保証しない |

最新版で実設定・モデルを除外していても、旧入口やクラス生成が安全になったとはしていません。旧 `test_notify.py` と `test_run.py` も実行対象から外します。新規検証では原本モジュールをimportせず、人工オブジェクトだけを使います。

型宣言93フィールドの範囲を示す資料です。router等の動的辞書設定、旧スクリプト固有の追加キーまで網羅した運用設定の保証ではありません。元の設定生成コードと利用側の参照を別途照合する必要があります。
