# セキュリティ・公開可否の確認事項

更新目的：Privateリポジトリの現状を記録し、整理・公開時に必要な確認を漏らさないこと。

## 2026年11月7日の初期調査

| 項目 | 状態 | 判断 |
| --- | --- | --- |
| GitHubの公開範囲 | Private | 維持 |
| `credentials.json` | Gitの管理対象として存在 | 内容を外部へ表示せず、認証状態の確認が必要 |
| `token.pickle` | Gitの管理対象として存在 | 中身をロードせず、失効・削除方針を確認 |
| `logs/`, `reports/` | 運用記録がGitに存在 | 注文・口座・取引情報の混入有無を未確認 |
| `config.yaml`, `config_backup/` | 設定や過去の設定がGitに存在 | 認証情報・環境固有値の精査が必要 |
| `model/`, `runtime/`, 各種`data/` | 学習成果物・データがGitに存在 | 配布可否・権利・容量・再現性の確認が必要 |
| `.gitignore` | 初期調査時点でなし | 新規追跡を抑える方針を追加。ただし既存追跡は解除されない |

## 取り扱いの原則

- **Privateだから安全と決めつけない。** 認証情報が有効なら、個別に失効・再発行の判断が必要。
- `.gitignore` の追加や最新コミットからのファイル削除では、過去のGit履歴からは消えない。
- 現在のリポジトリで履歴改変・force push・一括削除は実施しない。
- 認証トークン、取引明細、口座識別子、メール本文などの値を、Issue・PR・README・監査報告に貼り付けない。
- `pickle` 形式のファイルは、データを読むためにロードしない（任意コード実行の危険がある）。
- 売買API、ログイン自動化、Webhook送信、通知のテストを実口座や外部サービスへ接続して行わない。

## 公開を検討する場合の必要条件

1. 関係するAPI・OAuth資格情報が失効済みかを本人が確認する。
2. 公開可能なファイルだけを、**元の秘密を含むGit履歴を継承しない別リポジトリ**に選別する。
3. コード・設定・サンプルデータ・画像・文章について、機密情報、第三者の利用規約、個人情報の混入を精査する。
4. バックテストは将来の結果や利益を保証しないことを明記する。
5. 公開前に、第三者の視点からチェックを完了し、所有者が公開対象を最終承認する。

**現時点：公開不可（要追加確認）。**
